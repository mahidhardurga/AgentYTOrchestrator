Content writing agent: how we build it and which platform to use

A simple guide to two ways of building it, compared scenario by scenario, with a recommendation.

Part 1 · The basicsThe idea, the two options, and the answer first.

In 30 seconds

We want an AI helper that writes content on a schedule. A person reviews it, and then it goes to wherever we decide: an internal channel, a wiki, an email, or somewhere public later.

There are two good ways to build it. Claude Managed Agents is a ready-made workplace for AI agents. Amazon Bedrock is AI inside our own cloud, and we build the workplace around it.

The answer

It is a close call, and one question decides it.

Will the agent read confidential internal documents, or must all data stay inside our cloud?

  • Yes: choose Amazon Bedrock.
  • No: choose Claude Managed Agents. It takes about 10 working days to build, against about 19.

If we cannot answer yet, start a pilot on Managed Agents using public or low-sensitivity sources only. The pieces are designed so we can move to Bedrock later in about 1 to 2 weeks.

Middle option

Claude Platform on AWS gives Managed Agents through our AWS sign-in and billing. Anthropic still runs it, so the data question is the same.

What we are building

A writing helper with a safety net. It never sends anything out without a person approving it.

1. InputsTopic list, style samples, trusted websites.
→
2. The agentResearches, writes 3 drafts, checks them against a checklist.
→
3. A personPicks one, asks for changes, or skips.
→
4. DeliverySends the approved text to the chosen place.

The destination can change later without touching the agent. See Where the content goes.

Claude Managed Agents, simply

Think of renting a furnished office with a smart assistant already inside.

You describe the assistant's job once. The provider supplies everything around it: a safe workspace, a clock for schedules, a notebook that remembers, and a reviewer that checks work against a checklist. We only add the parts that touch our own systems.

Agent

The job description. Saved once and reused. Every edit is a new version.

Session

One working day. A single run from start to finish.

Memory

A notebook of small text files that survives between runs.

Grader

A second, independent reviewer that scores the work against our checklist.

It is in early release (beta) and works only with Claude.

Amazon Bedrock, simply

Think of buying a very good engine and a shop full of parts.

Bedrock gives us Claude inside our own cloud account. That is the thinking part. The workplace is up to us: a scheduler, a workflow that runs the steps in order, storage, safety filters, and a way to search trusted sites. We connect them ourselves.

Strong points

Data stays in our cloud. Company sign-in and logs. Built-in safety filters. Mature, reliable services.

Trade-offs

More to build and keep updated. No built-in web search. We build the checker loop and the memory.

Where the content goes

The destination is not decided, and it does not need to be. Delivery is the last step and can be swapped without touching the agent.

Approved textExactly what the reviewer approved.
→
Delivery stepOne small piece of code per destination.
Chat channel
A message in an internal channel.
Internal wiki
A page or draft.
Email
A newsletter draft.
Intranet page
Posted to the site.
Public site
Possible later, with extra review.

Some destinations ask for permission to be granted. That permission belongs to the delivery step. The agent never holds it. The first version can simply send the final text to the reviewer to place by hand.

Safety rules

These rules apply whenever content speaks for a person or the company, on either platform.

A person approves first

Nothing leaves the system without a named approver. Approval is tied to the exact text, so any edit needs approval again.

No personal logins

The agent never uses anyone's own account or password. It uses a dedicated team account that can be switched off.

Access is granted, not shared

If a destination needs permission, the content owner grants it once through that system's own sign-in screen. They can take it back at any time.

Hard limits

A maximum number of items per week, allowed times, and a stop switch that pauses everything.

Content rules

A list of topics that are off limits, sources required for facts, and a scan for sensitive data before anyone sees a draft.

Clear roles

Builders, operators and approvers are different people. The role that delivers cannot edit the code.

Everything is logged

Each run, draft, approval and delivery is recorded, with alerts for anything unusual.

Trial period

For the first few weeks, drafts go only to the reviewer. Nothing is delivered automatically.
