1Agent settings

Step 10.25 day

Set the model, tools and permissions on the existing agent. Every change creates a new saved version.

What to create or configure

  • Model: Claude Sonnet 5.5, effort high. Compare Claude Opus 5.5 in Step 17.
  • Tools: the built-in toolset with web search and page reading on. No tool that can send or publish anything.
  • Do not put site lists on the agent. The environment's host list (Step 2) controls where the web tools can go, so a data-source change never creates a new agent version.
  • Permission policy always_allow: the workspace is locked down and holds no secrets.
  • Record the agent ID and the new version number.

2Environment (the locked workspace)

Step 20.25 day

The environment decides which websites the agent's workspace can reach. The owner's data-source list drives it.

What to create or configure

  • One environment, content-writer-env, with limited networking.
  • Allowed hosts built from config/datasources.yaml, each listed with and without www.
  • No package installs and no outside tool servers.
  • Save the environment ID.
import yaml
def hosts(sites):
    out = []
    for s in sites:
        out += [s, "www." + s]       # a bare host matches only that exact host
    return out

cfg = yaml.safe_load(open("config/datasources.yaml"))
env = client.beta.environments.create(
    name="content-writer-env",
    config={"type": "cloud",
            "networking": {"type": "limited",
                           "allowed_hosts": hosts(cfg["sites"]),
                           "allow_package_managers": False,
                           "allow_mcp_servers": False}},
)
print(env.id)
config/datasources.yaml (maintained by the owner)
sites:
  - news.example.com
  - research.example.org
  - blog.example.net
notes:
  news.example.com: general technology and business news
  research.example.org: analyst and research reports
What happens
  • With limited networking, this list also controls the two web tools: a page outside it returns an error, and search results from other sites are dropped.
  • A host listed here is also reachable from the workspace, so list only sites you trust.
  • Changing the list affects new runs only. Runs already open keep their old list.
Check it: a test run can read a listed site and fails on any other site.

# setup/sync_config.py   run after every edit to config/
import os, yaml, anthropic
client = anthropic.Anthropic()
ENV_ID, STORE_ID = os.environ["ENVIRONMENT_ID"], os.environ["MEMORY_STORE_ID"]

def upsert(path, text):
    try:
        client.beta.memory_stores.memories.create(STORE_ID, path=path, content=text)
    except Exception:                      # the path already exists: replace its content
        mem = next(m for m in client.beta.memory_stores.memories.list(STORE_ID)
                   if m.path == path)
        client.beta.memory_stores.memories.update(
            mem.id, memory_store_id=STORE_ID, content=text)   # confirm this call in Step 7

def sync():
    cfg = yaml.safe_load(open("config/datasources.yaml"))
    client.beta.environments.update(ENV_ID, config={           # confirm this call in Step 7
        "type": "cloud",
        "networking": {"type": "limited", "allowed_hosts": hosts(cfg["sites"]),
                       "allow_package_managers": False, "allow_mcp_servers": False}})
    for root, _, names in os.walk("config"):
        for n in names:
            if n == "datasources.yaml":
                continue
            full = os.path.join(root, n)
            path = "/" + os.path.relpath(full, "config").replace(os.sep, "/")
            upsert(path, open(full).read())
    upsert("/datasources.md", render_datasources_md(cfg))

if __name__ == "__main__":
    sync()

# Audience
Who: technology and business leaders in North America.

# Tones
Analytical: evidence first, measured, one clear takeaway.
Conversational: plain, warm, speaks to the reader as "you".
Bold: takes a clear position and argues it, still fair and sourced.
Story-led: opens with a short real example, then draws the lesson.

Template: formats/linkedin.md
# LinkedIn format
Length: 900 to 1500 characters.
Hook: the first line makes one specific claim and is at most 200 characters.
Structure: short paragraphs of one to three sentences, with blank lines between.
Ending: one question or one takeaway, never both.
Hashtags: at most 3, at the end.
Do not: use a greeting, emoji, or tag real people.
Template: off-limits.md
# Off limits
Topics: non-public information about any company, financial forecasts, legal or
medical advice, politics, claims about named people.
Phrases: game-changer, in today's fast-paced world, revolutionary, <add more>

4Instructions (system prompt)

Step 40.25 day

The instructions tell the agent where things are and what to do in each of the two modes. Save them as agent/system.md and apply them with Step 1.

What to create or configure

  • Write agent/system.md from the text below.
  • Keep it short and stable. Themes, tones and formats live in memory so the owner can change them without a new agent version.
  • Re-apply with Step 1 whenever it changes.
# Role
You write LinkedIn posts for <OWNER>, for an audience of technology and business
leaders in North America. You work in one of two modes. The request tells you which.

# Where things are
- Notes (read-only): /mnt/memory/content-memory/
  themes.md, datasources.md, audience.md, tones.md, off-limits.md,
  formats/linkedin.md, voice/samples/*.md, history/*.md, feedback/*.md
- Save results to /mnt/session/outputs/

# Mode: propose
The request has: MODE: propose, THEMES (optional), COUNT (default 4).
1. Read themes.md (or the THEMES given), audience.md, off-limits.md and history/.
2. Search the allowed sites for what is trending or newly published for those themes.
3. Propose COUNT different topics. For each give a title, the theme, why it matters
   now, a suggested angle for our audience, and 2 to 3 sources.
4. Do not propose anything already in history/ or touching off-limits.md.
5. Save proposals.json and sources.json.

# Mode: draft
The request has: MODE: draft, TOPIC (text, or "proposal N" from the run so far),
ANGLE (optional), TONES (optional), DRAFTS (default 3), FORMAT (default linkedin).
1. Read audience.md, tones.md, formats/<FORMAT>.md, voice/, off-limits.md and the
   5 newest files in feedback/.
2. Research the topic on the allowed sites. Read the best 3 to 5 sources in full and
   copy the exact sentence for every fact you use.
3. Write DRAFTS drafts, each in a different tone. If TONES is not given, pick the
   tones that contrast most. Follow the format rules and check length with a tool.
4. For each draft add one line on how it differs from the others.
5. Add a short comparison and say which draft you would pick and why.
6. Save drafts.json and sources.json.

# Rules
- Use only the allowed websites. Never invent a quote, number, name or link.
- Every factual claim points to a source id in sources.json.
- Never include non-public information, personal data or anything in off-limits.md.
- Attribute facts to their source. Do not disparage any person or company.
- Do not ask questions. If something is unclear, choose the safest option and say so
  in the "notes" field.

6Checklists (grader)

Step 60.5 day

Each request starts with a checklist. A separate grader scores the work and sends weak results back to be fixed before a person sees them. There is one checklist per mode.

What to create or configure

  • Write agent/rubric_propose.md and agent/rubric_draft.md from the text below.
  • Start every run with a "define outcome" event holding the request, the matching checklist and a retry limit of 4.
  • Handle each result: satisfied goes to review normally. max_iterations_reached and failed still go to review, flagged "checklist not fully met".
  • Refine both checklists in Step 17 using real misses.
rubric_propose.md
1. proposals.json and sources.json exist and follow the agreed formats.
2. The requested number of topics, no two on the same story.
3. Every topic belongs to a listed theme.
4. Every topic has a specific reason it matters now, based on a dated source.
5. Every topic has an angle that fits the audience in audience.md.
6. Every topic has at least 2 sources, each with a link, date and exact quote.
7. No topic appears in history/ or touches off-limits.md.
8. Sources come only from the approved sites.
rubric_draft.md
1. drafts.json and sources.json exist and follow the agreed formats.
2. The requested number of drafts, each in a different named tone from tones.md.
3. Each tone is clearly recognizable and the drafts contrast with each other.
4. Each draft meets the length, hook and hashtag rules in the format file.
5. Every factual claim points to a source id that exists in sources.json.
6. Every source has an https link, a date and an exact quote.
7. No phrase from off-limits.md appears in any draft.
8. Each draft suits the audience: plain, specific, no hype, US spelling.
9. Each draft has one concrete example, number or short story.
10. Each draft ends with one question or one takeaway, never both.
11. contrast_note and comparison are present and honest.
def outcome(request_text, rubric_path, max_iterations=4):
    return {
        "type": "user.define_outcome",
        "description": request_text,
        "rubric": {"type": "text", "content": open(rubric_path).read()},
        "max_iterations": max_iterations,        # default 3, maximum 20
    }
Grader resultMeaningWhat our runner does
satisfiedAll items passedNormal review
needs_revisionAnother round is runningWait
max_iterations_reachedRetries used upReview, flagged "not fully met"
failedChecklist does not fit the requestReview, flagged, and alert the owner
interruptedSomeone stopped the runMark cancelled

The grader cannot browse the web. It judges form, tone and whether each claim points to a quote. Our own quote check in Step 10 proves the quotes are real.

Check it: a draft with a missing source, or two drafts in the same tone, is sent back and fixed within the retry limit.

# setup/run_once.py     python setup/run_once.py propose   |   python setup/run_once.py draft "topic"
import os, sys, time, anthropic
client = anthropic.Anthropic()
AGENT_ID, ENV_ID, STORE_ID = (os.environ[k] for k in
    ("CONTENT_AGENT_ID", "ENVIRONMENT_ID", "MEMORY_STORE_ID"))

def kickoff(request_text, rubric_path):
    return client.beta.sessions.create(
        agent={"type": "agent", "id": AGENT_ID, "version": int(os.environ["AGENT_VERSION"])},
        environment_id=ENV_ID,
        title=request_text.splitlines()[0],
        metadata={"project": "content-writer"},
        resources=[{"type": "memory_store", "memory_store_id": STORE_ID,
                    "access": "read_only",
                    "instructions": "Themes, data sources, audience, tones, formats, "
                                    "history and feedback. Read first."}],
        budget={"type": "limit", "max_list_cost": {"amount": "300", "currency": "USD"}},  # $3
        initial_events=[outcome(request_text, rubric_path)],
    )

def wait_finished(session_id):
    with client.beta.sessions.events.stream(session_id=session_id) as stream:
        for ev in stream:
            if (ev.type == "session.status_idle"
                    and ev.stop_reason.type not in ("requires_action", "budget_reached")):
                return "finished"
            if ev.type == "session.status_idle":
                return ev.stop_reason.type            # needs attention
            if ev.type == "session.status_terminated":
                return "terminated"

def fetch_outputs(session_id):
    for _ in range(4):                                # files appear after a short delay
        files = client.beta.files.list(scope_id=session_id,
                                       betas=["managed-agents-2026-04-01"]).data
        if files: return {f.filename: client.beta.files.download(f.id).read() for f in files}
        time.sleep(3)
    return {}

mode = sys.argv[1]
text = "MODE: propose\nCOUNT: 4" if mode == "propose" else f"MODE: draft\nTOPIC: {sys.argv[2]}\nDRAFTS: 3\nFORMAT: linkedin"
s = kickoff(text, f"agent/rubric_{mode}.md")
print("Watch it:", f"https://platform.claude.com/workspaces/default/sessions/{s.id}")
print(wait_finished(s.id))
for name, data in fetch_outputs(s.id).items():
    print(name, data[:300])
u = client.beta.sessions.retrieve(session_id=s.id).usage
print("cost:", u.list_cost, "active seconds:", u.active_seconds)

8Request runner (the commands you use)

Step 81 day

A small command line tool that starts requests, waits for results and passes your choices back to the agent. It is the only thing you operate day to day.

What to create or configure

  • Create runner/cli.py with the six commands below.
  • Keep each request's run (session) ID so a pick or a change request goes to the same run. The agent then still remembers its research.
  • If an old run is no longer available, start a new run seeded with the saved files from the earlier one.
  • After every finished run, call the same process_finished function (Steps 10 and 11).
# runner/cli.py
import argparse, sys
from sessions import kickoff, wait_finished, followup
from process import process_finished          # checks, document, notice (Steps 10, 11)
from state import new_request, get_request, set_status
from writeback import record_feedback         # Step 12

def run(request_text, rubric, mode):
    s = kickoff(request_text, rubric)
    rid = new_request(mode, s.id)
    print("Run started:", rid)
    set_status(rid, "running")
    result = wait_finished(s.id)
    if result == "finished":
        print("Review document:", process_finished(rid))
    else:
        print("Needs attention:", result)

def cmd_propose(a):
    text = "MODE: propose\n" + (f"THEMES: {a.themes}\n" if a.themes else "") + f"COUNT: {a.count}"
    run(text, "agent/rubric_propose.md", "propose")

def cmd_draft(a):
    text = f"MODE: draft\nTOPIC: {a.topic}\nDRAFTS: {a.drafts}\nFORMAT: {a.format}\n"
    if a.angle: text += f"ANGLE: {a.angle}\n"
    if a.tones: text += f"TONES: {a.tones}\n"
    run(text, "agent/rubric_draft.md", "draft")

def cmd_pick(a):                               # choose one of the proposals
    r = get_request(a.request_id)
    followup(r.session_id,
             f"MODE: draft\nTOPIC: proposal {a.proposal}\nDRAFTS: 3\nFORMAT: linkedin\n"
             "Use the research you already did.", "agent/rubric_draft.md")
    set_status(r.id, "running")
    wait_finished(r.session_id); print("Review document:", process_finished(r.id))

def cmd_revise(a):                             # ask for a change to one draft
    r = get_request(a.request_id)
    followup(r.session_id, f"Revise draft {a.draft}: {a.note}. Keep every other rule.",
             "agent/rubric_draft.md")
    set_status(r.id, "running")
    wait_finished(r.session_id); print("Review document:", process_finished(r.id))

def cmd_feedback(a):                           # tell the system what you chose
    record_feedback(a.request_id, a.chosen, a.note)

p = argparse.ArgumentParser(); sub = p.add_subparsers(required=True)

Step 100.75 day

What to create or configure

# runner/checks.py
import os, re, yaml
from urllib.parse import urlparse
import requests

ALLOWED = [s.lower() for s in yaml.safe_load(open("config/datasources.yaml"))["sites"]]
FORMATS = {"linkedin": {"min": 900, "max": 1500, "hook_max": 200, "max_hashtags": 3, "drafts": 3}}
# keep these numbers in step with config/formats/linkedin.md

def host_ok(url):
    u = urlparse(url); h = (u.hostname or "").lower()
    return u.scheme == "https" and any(h == s or h.endswith("." + s) for s in ALLOWED)

def norm(s):
    s = s.replace("\u2019", "'").replace("\u201c", '"').replace("\u201d", '"')
    return re.sub(r"\s+", " ", s.replace("\u2013", "-").replace("\u2014", "-")).strip().lower()

def fetch_text(url, hops=3):
    for _ in range(hops):
        if not host_ok(url):
            return None                              # never fetch outside the approved list
        r = requests.get(url, timeout=15, allow_redirects=False, stream=True,
                         headers={"User-Agent": "content-writer-check"})
        if r.is_redirect:
            url = r.headers.get("location", ""); continue
        body = r.raw.read(2_000_000, decode_content=True).decode("utf-8", "ignore")
        body = re.sub(r"<(script|style).*?</\1>", " ", body, flags=re.S | re.I)
        return norm(re.sub(r"<[^>]+>", " ", body))
    return None

SENSITIVE = [re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+"),
             re.compile(r"\b(?:\d[ -]?){13,16}\b"),
             re.compile(r"(?i)\b(api[_-]?key|secret|password|token)\b\s*[:=]\s*\S+")]

def check_sources(sources):
    failed = []
    for s in sources:
        page = fetch_text(s["url"])
        if page is None or norm(s["quote"]) not in page:
            failed.append(s["id"])
    return failed

def check_drafts(drafts, sources, off_limits, fmt="linkedin"):
    f = FORMATS[fmt]; ids = {s["id"] for s in sources}
    r = {"quotes_failed": check_sources(sources), "claims_unmapped": [], "length": [],
         "hook": [], "hashtags": [], "sensitive": [], "off_limits": [],
         "count_wrong": len(drafts["drafts"]) != f["drafts"],
         "tone_repeated": len({d["tone"] for d in drafts["drafts"]}) != len(drafts["drafts"])}
    for d in drafts["drafts"]:
        n = len(d["text"])
        if not f["min"] <= n <= f["max"]: r["length"].append((d["id"], n))
        if len(d["hook"]) > f["hook_max"] or not d["text"].startswith(d["hook"]): r["hook"].append(d["id"])
        if len(d.get("hashtags", [])) > f["max_hashtags"]: r["hashtags"].append(d["id"])
        for c in d["claims"]:
            if c["source_id"] not in ids: r["claims_unmapped"].append((d["id"], c["claim"]))
        if any(p.search(d["text"]) for p in SENSITIVE): r["sensitive"].append(d["id"])
        if any(p.lower() in d["text"].lower() for p in off_limits): r["off_limits"].append(d["id"])
    r["ok"] = not any(v for k, v in r.items() if k != "ok")
    return r

The quote check only fetches over https from the approved list, follows at most three redirects, and each redirect must also be on the list. Without this, a bad link in the agent's output could make our code fetch an internal address.

Check it: a made-up quote, a missing source, a short draft, a long hook, two drafts in one tone, and an off-limits word each appear in the report.

# runner/jobs.py
def poll():
    for run in recent(client.beta.deployment_runs.list(deployment_id=DEPLOYMENT_ID)):
        if run.error:
            alert_once("high", f"Scheduled run failed: {run.error.type}", run.id); continue
        if run.session_id and not get_by_session(run.session_id):
            new_request("propose", run.session_id, source="schedule")
    for r in requests_with_status("running"):
        s = client.beta.sessions.retrieve(session_id=r.session_id)
        if s.status == "idle":
            reason = latest_idle_stop_reason(r.session_id)
            if reason == "budget_reached":
                set_status(r.id, "failed"); alert_once("high", "Run paused at its cap", r.id)
            elif reason != "requires_action":
                process_finished(r.id)                      # safe to run twice
        elif s.status == "terminated":
            set_status(r.id, "failed"); alert_once("high", "Run ended early", r.id)
        elif minutes_since(r.updated_at) > 45:
            alert_once("medium", "Run is taking too long", r.id)

def latest_idle_stop_reason(session_id):
    last = None
    for ev in client.beta.sessions.events.list(session_id=session_id).data:   # oldest first
        if ev.type == "session.status_idle":
            last = ev
    return last.stop_reason.type if last and last.stop_reason else None
